## 2. OpenAI: документация и живые пробы

Идентификатор `gpt-6-luna` сохранён: [страница модели](https://developers.openai.com/api/docs/models/gpt-6-luna) указывает входные изображения, streaming и Structured Outputs. `GET /v1/models/gpt-6-luna` вернул HTTP 200; ниже отдельно зафиксированы успешные генерации.

Все пробы выполнены без инструментов и автоматических повторов, со стандартной обработкой, `reasoning.effort=none` и `store=false`. Изображение — собственный синтетический красный PNG 64×64, не пользовательская фотография.

| Живая проверка | Результат |
| --- | --- |
| Подсчёт полного входа vision + strict JSON schema, `detail=low` | HTTP 200, `input_tokens=55` |
| Vision/JSON schema, `max_output_tokens=96` | HTTP 200, `completed`; schema валидна, цвет определён как красный. Usage: 55 input / 14 output, reasoning и cache — 0. Длительность 2373 мс |
| Текстовый поток, `max_output_tokens=32` | Успешный SSE-поток, два реальных text delta, `response.completed`, ожидаемый `STREAM_OK`. Usage: 12 input / 6 output, reasoning — 0; первый текст 1629 мс, весь ответ 1767 мс |

Это проверка возможностей API на небольших фикстурах, а не оценка качества гардероба на 20 фотографиях или production-валидация. Оценка токенной стоимости двух генераций: `67 × $0.10 / 1 000 000 + 20 × $0.50 / 1 000 000 = $0.0000167`. Это не счёт провайдера; оплата метода подсчёта входа отдельно не подтверждена.

Для стандартного режима обработки и короткого контекста до 272 000 токенов опубликованы следующие цены за миллион токенов: вход $0.10, запись кеша $0.125, кешированный вход $0.01, выход $0.50. Источники: [тарифы OpenAI](https://developers.openai.com/api/docs/pricing) и [страница модели](https://developers.openai.com/api/docs/models/gpt-6-luna). Расчёт ниже не включает инструменты, региональные надбавки или ускоренный режим.

При принятом лимите чата 12 000 входных и 600 выходных токенов:

| Расчёт | Верхняя оценка при указанных условиях |
| --- | --- |
| Обычный вход и выход | `12 000 × $0.10 / 1 000 000 + 600 × $0.50 / 1 000 000 = $0.0015` |
| Консервативная оценка с ценой записи кеша для всего входа | `12 000 × $0.125 / 1 000 000 + 600 × $0.50 / 1 000 000 = $0.0018` |
| Оценка с запасом 20% | `$0.00216 = 2160 microUSD` |

Это расчёт для baseline чата, а не измеренная стоимость полного приложения. Его применимость требует ограничить ввод/вывод и исключить надбавки. `max_output_tokens` ограничивает оплачиваемый выход, включая reasoning; финансовый адаптер сверяет фактический usage.

В проверенных [руководстве vision](https://developers.openai.com/api/docs/guides/images-vision) и [калькуляторе стоимости изображений](https://developers.openai.com/api/docs/guides/image-cost-calculator) не найден подтверждённый коэффициент для Luna. Коэффициент Astra `1.2` не переносится на Luna.

[Count input tokens](https://developers.openai.com/api/docs/guides/token-counting), `POST /v1/responses/input_tokens`, проверен для мультимодального входа и строгой schema: значение 55 совпало с usage генерации. В пробе совпадали model/input/text.format; reasoning, output cap, store и service tier добавлены при генерации. Рабочая основа резерва — считать неизменяемый payload, включая те же bytes изображения, `detail`, model ID и `text.format`/schema, затем ограничивать output. Различия между подсчитанным и отправленным payload недопустимы.

Кандидат финансовой формулы: `R = ceil_microUSD(((T_count × maxInputPrice + outputCap × outputPrice) / 1 000 000) × 1.2)`, где `maxInputPrice=$0.125`, `outputPrice=$0.50` за миллион токенов. Скидка кешированного входа в резерве не используется, неопределённые исходы удерживают резерв. Метод показал применимость на фикстуре, но не гарантирует полный предел всех платежей: стоимость/ограничения самого count-метода ещё требуют проверки и при наличии оплаты входят в бюджет до dispatch. Неизвестный резерв не допускает платный запрос. Эти финансовые проверки и guards относятся к адаптеру этапа 4, а не создают новый блокер этапа 0.

Успешная геолокация и работа в браузере не подтверждены: заголовок CORS при ошибке не доказывает успешный сценарий. [Пробный режим ipapi.co](https://ipapi.co/free/) требует обращения с рабочим email; постоянный бесплатный доступ не гарантируется. Провайдер пока не меняется. Независимый основной сценарий ручного поиска подтверждён на уровне API Geocoding; интерфейс и E2E будут проверены при реализации.

## 5. Итог этапа 0 и следующие проверки

Docker Desktop первоначально не запускался из-за оставшегося `~/Library/Containers/com.docker.docker/Data/vms/0/hyperkit.pid`: файл от 27 мая 2024 года содержал PID 15206 отсутствующего процесса. Журнал и окно ошибки показали `Failed to set up pidfile`, exit code 1 / WaitStatus 256. HyperKit создаёт PID-файл с `O_CREAT|O_EXCL`: [исходный код, setup_pidfile](https://github.com/moby/hyperkit/blob/master/src/hyperkit.c). Пользователь переименовал файл и запустил Docker; последующая проверка получила версии и клиента, и сервера `29.8.2`, Compose `5.6.0`, без ошибки. Препятствие этапа 0 устранено. PostgreSQL с постоянным томом проверяется на этапе 1.

После выбора pnpm metadata-only проверка разрешения зависимостей повторена успешно. Доступ модели, изображение, strict schema, поток, usage и время первого текста уже проверены; погодные API работают. Автоопределение ipapi.co пока недоступно, согласованный ручной выбор остаётся рабочим вариантом.

Принятый scope не меняется. Качество распознавания реальных вещей, финансовые guards и интерфейсные сценарии проверяются в соответствующих этапах реализации.
