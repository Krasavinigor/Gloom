# Одежда под погоду

Статус: рабочее описание идеи и требований первой версии.
Дата: 10 октября 2026 года.

Документ разделяет исходные требования пользователя и предложенные уточнения. Уточнения с соответствующей пометкой требуют подтверждения перед реализацией.

## 1. Идея проекта

Веб-приложение помогает пользователю выбрать одежду из собственного гардероба под погодные условия. Пользователь загружает фотографии вещей, AI предлагает их описание, а пользователь проверяет и при необходимости исправляет результат. Сохранённый гардероб используется для подбора от одного до трёх образов под погоду в выбранном месте.

Основное обещание продукта: «Помочь выбрать комфортный образ из своей одежды под погоду».

На странице подбора фон генерируется в зависимости от погоды.

## 2. Цель для портфолио

Создать законченный pet project для портфолио Frontend engineer с опытом интеграции GenAI/LLM.

Проект должен демонстрировать:

- Удобный пользовательский путь от загрузки фотографии до получения образа.
- Интеграцию мультимодальной модели для распознавания одежды и получения структурированного описания.
- Интеграцию LLM для подбора сочетаний из сохранённых вещей.
- Интеграцию генерации изображений для погодного фона.
- Работу с внешними погодными данными.
- Редактирование результатов AI, сохранение данных и обработку неопределённости.
- Качественный адаптивный интерфейс со состояниями загрузки, ошибок и отсутствия данных.

## 3. Границы первой версии

В первую версию входят:

1. Загрузка фотографии одежды.
2. Получение описания вещи с помощью AI.
3. Проверка и ручное редактирование описания пользователем.
4. Сохранение фотографии и описания в личном гардеробе.
5. Просмотр гардероба и редактирование сохранённых карточек.
6. Отдельная страница подбора одежды.
7. Предложение местоположения по IP и возможность выбрать место вручную.
8. Получение погоды для выбранного места.
9. Подбор от одного до трёх подходящих образов из вещей пользователя.
10. Генерация фона страницы в зависимости от погоды.

Предлагаемые ограничения первой версии: один предмет на фотографии, повседневная одежда на сегодня, без виртуальной примерки. Эти ограничения требуют подтверждения.

## 4. Основной пользовательский сценарий

1. Пользователь открывает гардероб и загружает фотографию вещи.
2. Приложение показывает статус обработки фотографии.
3. AI предлагает описание предмета.
4. Пользователь проверяет описание, исправляет неточности и сохраняет карточку.
5. Пользователь переходит на страницу подбора одежды.
6. Приложение предлагает место по IP либо пользователь выбирает его вручную.
7. Приложение получает погодные условия и показывает их пользователю.
8. На основе погоды и сохранённого гардероба приложение предлагает от одного до трёх образов.
9. Пользователь просматривает реальные фотографии вещей в каждом образе.
10. Страница получает фон, сгенерированный в зависимости от погоды.

## 5. Требования к гардеробу

### 5.1. Загрузка и распознавание

- Пользователь может загрузить фотографию предмета одежды.
- Приложение проверяет допустимость файла перед обработкой; конкретные форматы и ограничения размера будут определены позднее.
- Мультимодальная модель предлагает структурированные характеристики предмета.
- Результат распознавания показывается в редактируемой карточке до сохранения.
- При неудачном распознавании пользователь получает понятное сообщение и возможность повторить попытку или заполнить описание вручную.

### 5.2. Описание предмета

Исходные обязательные данные карточки:

| Поле | Требование | Пример |
| --- | --- | --- |
| Название | Понятное название предмета | Синяя джинсовая куртка |
| Тип одежды | Категория предмета | Куртка, футболка, штаны, ботинки |
| Область тела | Одна или несколько областей | Ступни, ноги, корпус, голова |
| Сезонность | Подходящий сезон или несколько сезонов | Зима, весна/осень, лето |
| Температурный диапазон | Предварительная оценка условий использования либо «неизвестно» | Ориентировочный диапазон, уточняемый пользователем |
| Фотография | Сохранённое изображение загруженного предмета | Фото вещи пользователя |

Предлагаемое расширение описания для корректного подбора сочетаний (требует подтверждения):

- Слой одежды: базовый, промежуточный, верхняя одежда; для обуви и других предметов — «не применимо».
- Цвет и рисунок.
- Ориентировочная теплота.
- Защита от дождя и ветра, если она известна.

Категория и область тела не заменяют друг друга: футболка и куртка относятся к корпусу, но занимают разные слои. Предмет может покрывать несколько областей тела, например платье.

### 5.3. Неопределённость и исправления

- Температурный диапазон является ориентиром, а не гарантией комфорта.
- Комфорт зависит от сочетания вещей, погодных условий, активности и особенностей человека.
- Модель не должна выдавать состав ткани, утепление или водонепроницаемость за установленный факт, если это нельзя определить по фотографии.
- Неопределённые свойства допускают значение «неизвестно» и могут уточняться пользователем.
- Пользователь может изменить предложенное название и характеристики до сохранения и после него.
- Исправленные значения сохраняются и используются при дальнейшем подборе.
- Повторная обработка AI не должна незаметно перезаписывать исправления пользователя.

## 6. Требования к местоположению и погоде

- Приложение предлагает приблизительное местоположение по IP.
- Определённое место явно показывается пользователю и доступно для изменения.
- Ручной выбор места работает независимо от успеха определения по IP.
- Погода получается из внешнего источника данных, а не из предположений LLM.
- Для подбора учитываются температура, ощущаемая температура, ветер и осадки.
- На странице отображаются выбранное место, погодные условия и время актуальности данных.
- При изменении места обновляются погода и предложения образов.
- При недоступности погодного источника приложение сообщает об ошибке и позволяет повторить запрос; вымышленные данные не используются.

IP может давать неточное местоположение, особенно при использовании VPN. Сезонность вещей не заменяет проверку фактической погоды.

## 7. Требования к подбору образов

- Подбор находится на отдельной странице.
- Образ состоит исключительно из сохранённых вещей пользователя.
- При наличии подходящих сочетаний приложение предлагает от одного до трёх образов.
- Если подходящих сочетаний меньше трёх, приложение показывает доступное количество.
- Если подходящего полного комплекта нет, приложение объясняет, чего не хватает; оно не выдумывает отсутствующие вещи и не выдаёт неподходящий комплект за подходящий.
- Подбор учитывает категории предметов, их совместимость и погодные ограничения.
- LLM предлагает сочетания, а приложение проверяет наличие выбранных предметов в гардеробе и допустимость состава комплекта.
- В образе отображаются фотографии и названия выбранных вещей.
- При пустом гардеробе приложение предлагает добавить вещи.
- При ошибке AI пользователь может повторить подбор без потери гардероба.

Предлагаемые уточнения подбора (требуют подтверждения):

- Для каждого образа показывается короткое объяснение выбора с учётом погоды.
- Неизвестные свойства, важные для рекомендации, явно отмечаются, например неподтверждённая защита обуви от дождя.

## 8. Требования к генерируемому фону

- Фон страницы подбора генерируется на основе погодных условий.

Предлагаемые уточнения поведения фона (требуют подтверждения):

- Генерация выполняется асинхронно и не задерживает показ погоды и готовых образов.
- До готовности изображения и при ошибке генерации используется предусмотренный запасной фон.
- Фон не ухудшает читаемость текста и доступность элементов управления.
- Предусматривается повторное использование сгенерированных фонов для сходных погодных условий, чтобы избегать лишних запросов.
- Фон служит оформлением страницы; фактическая погода отображается отдельно текстом и числами.

## 9. Качество интерфейса и интеграций

- Основной сценарий удобен на мобильном устройстве и на компьютере.
- Формы и элементы управления доступны с клавиатуры и имеют понятные подписи.
- Для загрузки, распознавания, сохранения, получения погоды, подбора и генерации фона предусмотрены состояния ожидания и ошибок.
- Ошибки внешних сервисов не приводят к потере сохранённых вещей и пользовательских исправлений.
- Ответы AI проверяются перед сохранением и отображением; результат модели не считается автоматически корректным.
- Загруженные фотографии и гардероб не публикуются без действия пользователя.
- Секреты внешних сервисов не раскрываются в клиентском приложении.

## 10. Критерии готовности первой версии

- Пользователь может пройти полный путь от загрузки фотографии до сохранённой карточки вещи.
- После повторного открытия приложения сохраняются фотография, описание и пользовательские правки.
- Пользователь может выбрать место вручную и получить погоду для него.
- Подбор использует сохранённые характеристики и возвращает только вещи из гардероба.
- При достаточном гардеробе пользователь получает от одного до трёх подходящих комплектов.
- При нехватке вещей, неизвестных свойствах и сбоях сервисов приложение показывает соответствующее состояние.
- Погодный фон генерируется в зависимости от погодных условий.
- Основные сценарии работают на мобильном устройстве и доступны с клавиатуры.

## 11. Отложенные возможности

Обратная связь «холодно / комфортно / жарко» и персонализация на её основе — дополнительная фича на будущее.

Она не входит в первую версию. Сейчас не проектируются её интерфейс, модель данных, алгоритм и интеграция. Сам подбор образов под погоду остаётся основной функцией проекта.

## 12. Технологические решения и открытые вопросы

### 12.1. Принятые решения

- Next.js с React — основа приложения.
- SSR — выбранное направление рендеринга.
- OpenAI API — провайдер AI; пользователь подтвердил доступ к API.

### 12.2. Рабочие рекомендации и кандидаты

- TypeScript — рабочая рекомендация для языка разработки, требует подтверждения.
- Серверный рендеринг начальных страниц и данных, клиентская обработка интерактивных действий — предлагаемое применение SSR.
- Публичные погодные данные можно кешировать отдельно; персональный гардероб не должен попадать в общий кеш.
- `gpt-6-luna` и `gpt-image-2.5-flare` — кандидаты для проверки качества, скорости и стоимости; конкретные модели не утверждены.
- Остальные библиотеки, Vercel и Open-Meteo остаются предложениями, а не принятыми решениями.

### 12.3. Открытые вопросы

- Конкретные AI-модели, библиотеки, хостинг и внешние сервисы для погоды и местоположения.
- Авторизация, способ хранения фотографий и данных гардероба.
- Справочник категорий, шкала теплоты и правила проверки комплектов.
- Учёт времени выхода, длительности и сценария активности; для базовой версии предложен подбор на сегодня.
- Возможность заменить отдельную вещь в предложенном образе.
- Удаление вещи и поведение ранее предложенных образов после изменений гардероба.
- Демонстрационный гардероб для посетителей портфолио.
- Бюджет, ограничения запросов и целевое время ожидания операций AI.

Этот документ фиксирует продуктовую идею и рабочие требования. Детальная архитектура, контракты API и план реализации будут определены отдельно.
