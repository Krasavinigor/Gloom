# Одежда под погоду

Статус: Scope первой версии уточнён: готовые погодные фоны и SSE для статусов; новых функций не добавлено.
Дата: 12 октября 2026 года.

Документ фиксирует согласованные продуктовые требования первой версии и принятый технический baseline из [плана реализации](IMPLEMENTATION_PLAN.md). Фактическая доступность моделей, тарифы, версии пакетов и детали интеграций проверяются при реализации; эти проверки не являются повторным согласованием scope.

## 1. Идея проекта

Веб-приложение помогает пользователю выбрать одежду из собственного гардероба под погодные условия. Пользователь загружает фотографии вещей, AI предлагает их описание, а пользователь проверяет и при необходимости исправляет результат. Сохранённый гардероб используется для подбора от одного до трёх образов под погоду в выбранном месте.

Основное обещание продукта: «Помочь выбрать комфортный образ из своей одежды под погоду».

На странице подбора фон выбирается по погоде из заранее подготовленного каталога.

## 2. Цель для портфолио

Создать законченный pet project для портфолио Frontend engineer с опытом интеграции GenAI/LLM.

Проект должен демонстрировать:

- Удобный пользовательский путь от загрузки фотографии до получения образа.
- Интеграцию мультимодальной модели для распознавания одежды и получения структурированного описания.
- Интеграцию LLM для подбора сочетаний из сохранённых вещей.
- Контекстный диалог о погоде и одежде с потоковым ответом LLM: текст появляется по мере поступления реальных фрагментов.
- Отображение погодных данных в интерфейсе: детерминированный выбор подходящей иллюстрации.
- Работу с внешними погодными данными.
- Редактирование результатов AI, сохранение данных и обработку неопределённости.
- Качественный адаптивный интерфейс со состояниями загрузки, ошибок и отсутствия данных.

## 3. Границы первой версии

В первую версию входят:

1. Загрузка фотографии одежды.
2. Получение описания вещи с помощью AI.
3. Проверка и ручное редактирование описания пользователем.
4. Сохранение фотографии и описания в личном гардеробе.
5. Просмотр гардероба и редактирование сохранённых карточек.
6. Отдельная страница подбора одежды.
7. Предложение местоположения по IP и возможность выбрать место вручную.
8. Получение погоды для выбранного места.
9. Подбор от одного до трёх подходящих образов из вещей пользователя.
10. Выбор погодного фона из 8–16 заранее подготовленных изображений.
11. Замена отдельной вещи в готовом образе без нового запроса LLM.
12. Удаление вещей с подтверждением.
13. Отдельный демонстрационный режим с готовыми примерами.
14. Небольшое окно чат-бота на странице подбора с потоковыми ответами о погоде и образах.

Подбор рассчитан на повседневную активность в течение трёх часов с момента запуска. Переключателя активности и выбора времени выхода или длительности в первой версии нет.

Одна фотография соответствует одной вещи и содержит один основной предмет одежды.

Виртуальная примерка не входит в первую версию.

### 3.1. Демонстрационный режим

- Отдельный режим позволяет посетителю портфолио изучить готовые примеры без запросов OpenAI.
- Ориентир наполнения — 15 вещей и три сценария: тепло, прохладно и ветрено, дождь. Образы, объяснения и примеры вопросов и ответов чата подготовлены заранее; фоны используют тот же каталог, что личный режим.
- Сценарии используют фиксированные примеры погоды и явно помечаются «Демонстрация: пример погодных условий». Они не показываются как текущий прогноз или персональный период «сейчас + 3 часа».
- Демо изолировано от личного гардероба. Загрузка, редактирование и удаление в демо недоступны; эти действия доступны только в личном режиме.
- Для демонстрационных фотографий используются собственные изображения или изображения с разрешением на использование.
- Личный режим сохраняет реальное получение погоды и интеграцию OpenAI согласно остальным требованиям документа.

## 4. Основной пользовательский сценарий

1. Пользователь открывает гардероб и загружает фотографию вещи.
2. Приложение показывает статус обработки фотографии.
3. AI предлагает описание предмета.
4. Пользователь проверяет описание, исправляет неточности и сохраняет карточку.
5. Пользователь переходит на страницу подбора одежды.
6. Приложение восстанавливает сохранённое место; если его нет, предлагает место по IP. Пользователь может выбрать место вручную в любой момент.
7. Приложение получает погодные условия и показывает их пользователю.
8. Пользователь явно запускает подбор. Приложение фиксирует период от момента запуска до трёх часов спустя и предлагает от одного до трёх образов на основе погоды за этот интервал и сохранённого гардероба.
9. Пользователь просматривает реальные фотографии вещей в каждом образе.
10. Успешный ручной подбор выбирает фон из каталога по своему погодному snapshot и сохраняет идентификатор фона вместе с результатом. Подгрузка изображения не задерживает показ образов.

### 4.1. Дополнительный сценарий: диалог о погоде и одежде

- На странице подбора пользователь может открыть и закрыть небольшое окно чат-бота, отправлять вопросы и получать ответы о погоде и наборах одежды.
- Примеры вопросов: «Почему в этом образе куртка?» и «Ожидается ли дождь в ближайшие три часа?».
- Ответы учитывают предыдущие сообщения текущей беседы: вопрос «А худи достаточно?» после обсуждения куртки связан с предыдущим ответом. Численные лимиты приняты в [разделе 7 плана реализации](IMPLEMENTATION_PLAN.md#7-потоковый-чат).
- Ответ появляется постепенно по мере поступления реальных фрагментов от модели через сервер. Приложение не ждёт весь ответ и не имитирует поток анимацией заранее полученного полного текста.
- Интерфейс различает отправку сообщения, ожидание первых фрагментов, генерацию и готовность ответа. Готовность означает подтверждённое успешное завершение; закрытие соединения само по себе не считается успехом.
- Пользователь может остановить получение ответа. При остановке или обрыве уже полученный текст остаётся видимым и отмечается незавершённым; повторная попытка возможна только вручную.
- Фрагменты разных запросов не смешиваются. Открытие окна и обновление страницы не создают запросов AI; платная операция запускается только отправкой сообщения, без автоматических повторов.
- Остановка получения на клиенте не гарантирует остановку операции у провайдера или отсутствие расходов.

Контекст и границы диалога:

- Сервер передаёт боту выбранное место и часовой пояс, полученную погоду с периодом и актуальностью, характеристики сохранённых вещей и последний результат подбора с признаком устаревания. Фотографии повторно не отправляются.
- Погодные факты берутся только из полученных данных источника; неизвестное обозначается явно, устаревший образ не выдаётся за актуальный.
- После изменения города или гардероба следующие ответы используют новое состояние. Старые сообщения сохраняют исходный контекст или соответствующую пометку.
- Чат объясняет и советует, но не изменяет вещи, место или образы и не запускает подбор либо новый выбор погодного фона.
- Текст ответа не является новым проверенным образом; для получения нового комплекта используется основной сценарий ручного запуска подбора.
- История сообщений хранится только в текущей вкладке, без БД: закрытие окна её не стирает, перезагрузка страницы очищает. Размер контекста ограничен принятым техническим baseline.
- В демо используются готовые примеры вопросов и ответов без OpenAI; свободный AI-диалог доступен только в личном режиме.

## 5. Требования к гардеробу

### 5.1. Загрузка и распознавание

- Поддерживаются JPEG, PNG и WebP. HEIC и анимированные изображения не поддерживаются.
- Одна фотография соответствует одной вещи и содержит один основной предмет. Если на фото несколько самостоятельных вещей, пользователь получает предложение загрузить их отдельно.
- Размер входного файла — не более 10 МБ, декодированного изображения — не более 40 мегапикселей, длинной стороны — не более 8192 пикселей.
- Перед отправкой в AI пользователь видит превью. Сервер проверяет реальное содержимое, формат и размеры; при превышении лимита показывает понятную причину до платного запроса.
- При обработке сервер исправляет ориентацию и удаляет метаданные, включая GPS. В локальной папке сохраняется обработанная фотография с длинной стороной не более 2048 пикселей; копия для AI — не более 1536 пикселей. Маленькие изображения не увеличиваются.
- Сохранение исходника с EXIF не предполагается: локально хранится обработанная фотография.
- Мультимодальная модель предлагает структурированные характеристики предмета.
- Результат распознавания показывается в редактируемой карточке до сохранения.
- При неудачном распознавании пользователь получает понятное сообщение и возможность повторить попытку или заполнить описание вручную.

### 5.2. Описание предмета

Обязательные данные карточки:

| Поле | Требование | Пример |
| --- | --- | --- |
| Название | Понятное название предмета | Синяя джинсовая куртка |
| Тип одежды | Категория и тип из справочника | Верхняя одежда: куртка |
| Область тела | Одна или несколько областей | Ступни, ноги, корпус, голова |
| Сезонность | Подходящий сезон или несколько сезонов | Зима, весна/осень, лето |
| Температурный диапазон | Предварительная оценка условий использования либо «неизвестно» | Ориентировочный диапазон, уточняемый пользователем |
| Фотография | Сохранённое обработанное изображение | Фото вещи пользователя |

Справочник категорий:

| Категория | Типы |
| --- | --- |
| Верх | Футболка, лонгслив, рубашка |
| Средний слой | Свитер, худи, кардиган |
| Верхняя одежда | Куртка, пальто, дождевик, жилет |
| Низ | Брюки, джинсы, шорты, юбка, леггинсы |
| Цельная одежда | Платье, комбинезон |
| Обувь | Кроссовки, туфли, ботинки, сапоги, сандалии |
| Головные уборы | Шапка, кепка, панама |
| Другое | Предмет можно сохранить; для автоматического подбора требуется уточнить его роль |

Дополнительные характеристики:

- Допустимые слои: базовый, средний, верхний. У вещи может быть несколько допустимых слоёв, но в конкретном образе она занимает один. Для обуви и головных уборов слой — «не применимо».
- Цвет и рисунок.
- Теплота: лёгкая, средняя, тёплая, неизвестно. Оценка относительна внутри категории: тёплая футболка не приравнивается к тёплой куртке.
- Защита от дождя и ветра оценивается отдельно: подтверждена, отсутствует, неизвестно. Внешний вид не подтверждает защитные свойства.

Категория, область тела и слой — отдельные характеристики. Предмет может покрывать несколько областей одновременно: платье относится к корпусу и ногам.

### 5.3. Неопределённость и исправления

- Температурный диапазон является ориентиром, а не гарантией комфорта.
- Сезонность — подсказка, а температурный диапазон — эвристическая оценка. Теплоту вещей нельзя складывать или пересекать их температурные диапазоны как формулу комфорта комплекта.
- Комфорт зависит от сочетания вещей, погодных условий, активности и особенностей человека.
- Модель не должна выдавать состав ткани, утепление или водонепроницаемость за установленный факт, если это нельзя определить по фотографии.
- Неопределённые свойства допускают значение «неизвестно» и могут уточняться пользователем.
- Пользователь может изменить предложенное название и характеристики до сохранения и после него.
- Исправленные значения сохраняются и используются при дальнейшем подборе.
- Повторная обработка AI не должна незаметно перезаписывать исправления пользователя.

### 5.4. Редактирование и удаление

- Редактирование вещи сохраняет пользовательские правки и отмечает последний подбор как требующий обновления, без автоматического платного запроса.
- Удаление требует подтверждения. Подтверждённая вещь сразу исключается из гардероба и новых подборов; связанные с ней образы не показываются как актуальные.
- Фотография удаляется; её копии в результатах подбора не сохраняются.
- Если физический файл удалить не удалось, интерфейс явно показывает незавершённое удаление и позволяет повторить попытку. Атомарное удаление записи БД и файла не предполагается.

## 6. Требования к местоположению и погоде

- Сохранённое место имеет приоритет. Оно хранится на сервере и используется при SSR следующего открытия страницы.
- Только если сохранённого места нет, браузер после загрузки страницы запускает автоопределение по IP.
- Ручной выбор места — равноправный основной сценарий, доступный всегда и независимо от успеха определения по IP. Выбор сохраняется на сервере.
- Ручной поиск показывает список мест с городом, регионом и страной; пользователь выбирает конкретный результат.
- Место, определённое по IP, явно помечается как приблизительное, показывается пользователю и доступно для изменения.
- Поздний ответ автоопределения не заменяет место, выбранное пользователем вручную.
- При ошибке или превышении времени ожидания автоопределения пользователь выбирает место вручную; приложение не выдумывает местоположение.
- Названия города, региона и страны, проверенные координаты и часовой пояс относятся к одному выбранному месту и сохраняются вместе. Исходный публичный IP в БД не сохраняется.
- Погода получается через сервер Next.js из Open-Meteo Forecast, ручной поиск использует Open-Meteo Geocoding. Погодные данные не выводятся из предположений LLM; текущие условия Open-Meteo рассчитаны погодными моделями.
- Для подбора учитывается весь фиксированный трёхчасовой интервал: диапазоны обычной и ощущаемой температуры, ветер и порывы, ожидаемые осадки и их вероятность. Интервал может переходить через полночь; используется часовой пояс выбранного города.
- На странице отдельно отображаются выбранное место, погодные условия, время получения данных и период, к которому они относятся.
- При изменении места обновляется погода; готовый подбор отмечается как требующий обновления. Изменение места и обновление погоды сами не запускают платный AI.
- При недоступности погодного источника приложение сообщает об ошибке и позволяет повторить запрос. Если показываются ранее полученные данные, они помечаются устаревшими; новый подбор на них не запускается. Вымышленные данные не используются.

Условия сервисов, кеширование и атрибуция описаны в [разделе 12.7](#127-требования-к-погодным-сервисам-и-кешированию).

IP может давать неточное местоположение, особенно при использовании VPN. Сезонность вещей не заменяет проверку фактической погоды.

## 7. Требования к подбору образов

### 7.1. Комплектность и результат

- Подбор находится на отдельной странице.
- Подбор запускается явно пользователем для повседневной активности без переключателя сценария. Период «сейчас + 3 часа» фиксируется при запуске.
- Образ состоит исключительно из существующих сохранённых вещей пользователя, без повторов одной вещи внутри комплекта и с совместимыми ролями.
- Базовый комплект: базовый верх + низ + обувь либо платье/комбинезон + обувь. Куртка не заменяет базовый слой. Дополнительные слои и головной убор подбираются по погоде.
- При наличии подходящих сочетаний приложение предлагает от одного до трёх образов, различающихся составом вещей.
- Если подходящих сочетаний меньше трёх, приложение показывает доступное количество.
- При подтверждённой проверками нехватке подходящего полного комплекта приложение объясняет, чего не хватает; оно не выдумывает отсутствующие вещи и не выдаёт неподходящий комплект за подходящий.
- LLM предлагает сочетания и учитывает цвета как мягкое предпочтение. Приложение проверяет комплектность, роли, наличие вещей и погодные правила.
- Некорректный ответ AI или непрохождение проверок не выдаётся за отсутствие вещей в гардеробе. Допустимые варианты можно показать, отклонённые не выдаются как подходящие. Если допустимого результата ответа нет, показывается ошибка AI и возможность ручного повтора; прежний результат сохраняется с текущим статусом актуальности.
- В образе отображаются фотографии и названия выбранных вещей.
- Для каждого образа показываются короткое объяснение выбора и важные неизвестные свойства, например неподтверждённая защита обуви от дождя.
- При пустом гардеробе приложение предлагает добавить вещи.
- При ошибке AI пользователь может повторить подбор без потери гардероба.

### 7.2. Стартовые погодные эвристики

Правила применяются ко всему трёхчасовому интервалу. Минимум ощущаемой температуры используется для проверки холода; весь диапазон температур — также для проверки возможного перегрева.

| Минимальная ощущаемая температура | Стартовая проверка |
| --- | --- |
| Не выше 0 °C | Средний слой, тёплая верхняя одежда и тёплая закрытая обувь |
| Выше 0 °C, но ниже 10 °C | Верхняя одежда и закрытая обувь |
| От 10 °C включительно, но ниже 18 °C | Рассмотреть снимаемый дополнительный слой |

- Если ожидаются осадки или их вероятность не менее 50%, проверяется защита верхней одежды и обуви от дождя.
- Неподтверждённая защита не позволяет представить образ как полностью проверенный для дождя: вариант явно обозначается условным с объяснением ограничения и не выдаётся за соответствующий проверке.
- Это стартовые эвристики, подлежащие проверке при реализации, а не гарантия комфорта. Для первой версии сохраняются описанные правила без дополнительных численных порогов ветра и жары. При подборе слоёв модель учитывает ветер и весь диапазон температур за три часа; приложение продолжает проверять комплектность, существование вещей и описанные эвристики.

### 7.3. Замена вещи

- Пользователь нажимает «Заменить» и выбирает подходящую альтернативу той же роли и покрытия тела. Например, платье нельзя заменить одной футболкой.
- Остальные вещи в образе и другие образы сохраняются. После замены проверяется весь комплект по правилам комплектности и погоды.
- Если альтернатив нет, показывается причина и сохраняется прежний вариант.
- Замена не обращается к LLM и не создаёт расходов AI; объяснение обновляется на основе проверенных характеристик.
- Если подбор устарел, перед заменой требуется новый явный запуск подбора.

### 7.4. Сохранение последнего результата

- Хранится только последний результат из одного–трёх образов с выполненными заменами. Галереи истории нет.
- Результат сохраняется вместе с фиксированным периодом, использованной погодой и состоянием гардероба. Если интервал закончился или исходные данные изменились, он отмечается как требующий обновления; пользователю предлагается новый запуск.
- С результатом сохраняется `backgroundPresetId` выбранного фона из каталога; восстановление не требует AI.
- Обновление страницы восстанавливает последний результат, не смещает его период и не запускает платный AI.
- Неудачный новый запуск не стирает прежний результат; его статус актуальности определяется текущими исходными данными и периодом.
- Редактирование и удаление вещей обрабатываются согласно [разделу 5.4](#54-редактирование-и-удаление); результаты не содержат копий фотографий.

## 8. Требования к погодному фону

- Каталог содержит 8–16 собственных или разрешённых к использованию иллюстраций, включая нейтральный default-фон, подготовленных заранее вне приложения. Подготовка изображений не входит в текущую задачу пересмотра документов.
- Manifest связывает стабильные идентификаторы с публичными изображениями, поставляемыми вместе с приложением, и сведениями об источнике/разрешении. Пользовательские фотографии продолжают храниться отдельно и не становятся публичными.
- Фон выбирается детерминированно по погодным кодам snapshot: гроза → снег/смешанные осадки → дождь/морось → туман → облачность → ясно. Внутри группы используется фиксированный вариант manifest, без случайного выбора при reload. Для неизвестного кода или отсутствующего ресурса предусмотрен default-фон. Это правила оформления, а не дополнительные численные пороги ветра или температуры для одежды.
- Выбор нового фона связан только с успешным ручным подбором: `backgroundPresetId` сохраняется в последнем результате. При восстановлении актуального результата используется тот же preset; подгрузка изображения не задерживает показ образов.
- Фон не ухудшает читаемость текста и доступность элементов управления.
- Фон служит оформлением страницы; фактическая погода отображается отдельно текстом и числами.
- При смене города или устаревании исходного контекста образ помечается как требующий обновления, а нейтральный default-фон не выдаёт старую иллюстрацию за актуальную погоду. Новый погодный preset выбирается при следующем успешном ручном подборе. Открытие/refresh восстанавливают подходящий сохранённый preset или default; чат и обновление погоды сами не запускают новый выбор.
- Демо использует тот же каталог по своим фиксированным погодным примерам. Выбор и показ фона не обращаются к AI и не расходуют бюджет.

## 9. Качество интерфейса и интеграций

- Основной сценарий удобен на мобильном устройстве и на компьютере.
- Формы и элементы управления доступны с клавиатуры и имеют понятные подписи.
- Для загрузки, распознавания, сохранения, получения погоды, подбора, подгрузки фонового изображения и диалога предусмотрены состояния ожидания и ошибок.
- Окно чата, ввод, отправка и остановка ответа доступны с клавиатуры. При ошибке или обрыве потока полученный текст сохраняется с понятной пометкой; дальнейшие фрагменты не смешиваются с другим запросом.
- Ошибки внешних сервисов не приводят к потере сохранённых вещей и пользовательских исправлений.
- Структурированные результаты AI проверяются перед сохранением и отображением; результат модели не считается автоматически корректным. Текст диалога показывается потоком согласно разделу 4.1.
- Загруженные фотографии и гардероб не публикуются без действия пользователя.
- Секреты внешних сервисов не раскрываются в клиентском приложении.

## 10. Критерии готовности первой версии

- Пользователь может пройти полный путь от загрузки фотографии до сохранённой карточки вещи.
- Загрузка соблюдает форматы и лимиты раздела 5.1; пользователь видит превью, недопустимый файл отклоняется до платного запроса. Сохраняется обработанная фотография без метаданных.
- Карточка поддерживает согласованный справочник, отдельные категории, области тела и слои; пользователь может исправить характеристики и неизвестные свойства.
- После повторного открытия приложения сохраняются фотография, описание и пользовательские правки.
- Пользователь может выбрать место вручную и получить погоду для него.
- Сохранённый выбор места восстанавливается при следующем открытии страницы; поздний ответ автоопределения по IP не перезаписывает ручной выбор.
- Подбор явно запускается пользователем и учитывает весь фиксированный трёхчасовой интервал в часовом поясе выбранного города, включая переход через полночь.
- Готовый подбор восстанавливается без смещения периода и платной генерации. По завершении интервала или изменении исходных данных он отмечается как требующий обновления.
- При ошибке погодного источника старые данные явно помечаются устаревшими и не используются для нового подбора. Обновление погоды само не запускает платный AI.
- Подбор использует сохранённые характеристики и возвращает только вещи из гардероба.
- При достаточном гардеробе пользователь получает от одного до трёх подходящих комплектов.
- Образы различаются составом и проходят проверки комплектности и погодных эвристик; условный вариант с неподтверждённой защитой от дождя не выдаётся за полностью проверенный.
- Замена вещи сохраняет остальные вещи и образы, проверяет весь комплект и не обращается к LLM. Сохраняется только последний результат с заменами, без галереи истории.
- Удаление требует подтверждения, исключает вещь из новых подборов и не оставляет связанные образы актуальными; неудачное удаление файла явно показано и доступно для повтора.
- Демо показывает отдельные готовые вещи, сценарии, образы, объяснения и фоны с маркировкой погодных примеров, без OpenAI и без изменения личного гардероба.
- При нехватке вещей, неизвестных свойствах и сбоях сервисов приложение показывает соответствующее состояние.
- Погодный фон выбирается из каталога по сохранённому snapshot, восстанавливается по `backgroundPresetId` и имеет default-вариант без AI.
- Пользователь открывает и закрывает чат, задаёт вопросы о погоде и образах с учётом предыдущих сообщений беседы и видит реальные поступающие фрагменты ответа до его завершения. Можно остановить ответ; при остановке или обрыве частичный текст остаётся незавершённым, а готовность показывается только после подтверждённого успеха.
- Основные сценарии работают на мобильном устройстве и доступны с клавиатуры.

### 10.1. Приёмочные сценарии

| Сценарий | Ожидаемый результат |
| --- | --- |
| Загрузить фото, исправить описание, сохранить и перезапустить приложение | Обработанная фотография и пользовательские правки восстановлены; повторное распознавание не запускается |
| Получить реальные и выдуманные идентификаторы вещей либо подтвердить нехватку комплекта | Показаны только допустимые варианты из гардероба; если допустимого ответа нет, показана ошибка AI, а при подтверждённой нехватке — объяснение недостающих вещей. Неудача сохраняет прежний результат с его текущим статусом |
| Вручную запустить подбор, восстановить результат, получить неизвестный код или ошибку изображения | Фон детерминированно выбран из каталога и сохранён по ID; reload восстанавливает preset без AI, неизвестный код/ошибка дают default. При смене города старый образ отмечен неактуальным и показан default до нового успешного ручного подбора |
| Отправить вопрос в чат, затем связанный вопрос; остановить или оборвать поток | Реальный первый фрагмент виден до полного ответа, следующий вопрос учитывает беседу; частичный ответ остаётся незавершённым, повторы только ручные |
| Исчерпать общий бюджет AI | Нет новых платных операций распознавания, подбора и чата; чтение, редактирование, готовые результаты и каталог фонов доступны |
| Открыть демонстрационный режим | Показаны готовые погодные примеры, образы, фоны и ответы чата; запросов OpenAI и изменений личного гардероба нет |

## 12. Технологические решения и открытые вопросы

### 12.1. Принятые решения

- Scope первой версии уточнён 12 октября: runtime-генерация фона заменена готовым каталогом, статусы операций передаются через SSE. Остальной план принят; новых функций не добавлено.
- Next.js App Router с React — основа приложения; модульные границы и SSR/клиентская логика описаны в [разделе 3 плана](IMPLEMENTATION_PLAN.md#3-архитектура-и-границы-модулей).
- TypeScript — язык разработки.
- SSR — выбранное направление рендеринга.
- Tailwind CSS и shadcn/ui используются для оформления и компонентов интерфейса.
- TanStack Query используется для клиентских запросов и обновлений. Начальные данные загружаются через Server Components; SSR не зависит от TanStack Query.
- OpenAI API — провайдер AI; пользователь подтвердил доступ к API.
- Стартовая текстовая/мультимодальная модель — `gpt-6-luna` для распознавания, подбора и чата; доступность и возможности проверяются при реализации. Фон не использует image-модель или платный API.
- Бюджет AI — до $10 за календарный месяц UTC допуска операции, включая распознавание, подбор, чат, разработку и тесты; предупреждение при $8.
- Приняты дополнительные библиотеки `pg`, `zod`, `react-hook-form`, `@hookform/resolvers`, `openai`, `sharp` и инструменты проверки Vitest, Testing Library, Playwright; версии проверяются до установки.
- Локальный worker обеспечивает долговечные операции распознавания и подбора и очистку пользовательских фотографий. Статусы приходят по одному SSE-feed на вкладку; чат использует отдельный POST-поток SSE без автоматического возобновления платного запроса.
- Численные параметры чата, срок черновиков 24 часа, UTC-учёт бюджета и остальные решения [плана реализации](IMPLEMENTATION_PLAN.md) приняты как baseline, подлежащий проверке на реальных интеграциях.
- Фон — публичный каталог из 8–16 готовых изображений с manifest и `backgroundPresetId` результата; правила выбора описаны в [разделе 8](#8-требования-к-погодному-фону).
- На текущем этапе достаточно локального запуска приложения.
- Один локальный гардероб без регистрации и входа.
- PostgreSQL — БД для метаданных гардероба, работающая отдельным сервисом/сервером для дальнейшего масштабирования. К ней подключается сервер Next.js; браузер напрямую к БД не подключается.
- Docker Compose используется для локального запуска PostgreSQL отдельным сервисом на том же компьютере. Размещение БД за пределами локального этапа отложено.
- Knex используется для доступа к PostgreSQL на сервере Next.js.
- Фотографии хранятся отдельными файлами в локальной постоянной папке.
- Сохранённое место используется при SSR; автоопределение по IP запускается в браузере после загрузки только при отсутствии сохранённого выбора. Ручной выбор места доступен всегда и сохраняется серверно.
- Open-Meteo Forecast используется для погоды, Open-Meteo Geocoding — для ручного поиска места. На некоммерческом локальном этапе используется бесплатный API с атрибуцией.
- Подбор запускается пользователем для фиксированного периода «сейчас + 3 часа» и повседневной активности без переключателя. Готовый результат сохраняется с исходными данными.
- Серверный кеш погоды — 15 минут, поиска мест — 24 часа; правила описаны в [разделе 12.7](#127-требования-к-погодным-сервисам-и-кешированию).
- Справочник и характеристики одежды, загрузка и удаление согласованы в [разделе 5](#5-требования-к-гардеробу).
- Комплектность, стартовые погодные эвристики, замена без LLM и хранение только последнего результата согласованы в [разделе 7](#7-требования-к-подбору-образов).
- Отдельное демо с готовыми примерами без OpenAI согласовано в [разделе 3.1](#31-демонстрационный-режим).
- Диалог о погоде и одежде с реальным потоковым показом ответов, контекстом, режимом только вопросов и ответов, историей текущей вкладки и готовыми примерами в демо согласован в [разделе 4.1](#41-дополнительный-сценарий-диалог-о-погоде-и-одежде).

### 12.2. Кандидат геолокации

- Выбор времени выхода, длительности и спортивной активности отложен и сейчас не проектируется.

### 12.5. Требования к локальному гардеробу и хранению

- В приложении один гардероб, без функциональности пользователей, аккаунтов и сессий. Локальный сервер доступен только на этом компьютере; запросы, изменяющие данные, защищены от сторонних origin.
- Описания и фотографии сохраняются после закрытия браузера, перезапуска приложения и сервиса БД. SSR и клиентские изменения используют единое серверное хранилище.
- Данные PostgreSQL хранятся в постоянном томе и сохраняются после пересоздания контейнера при сохранении тома.
- Параметры подключения и учётные данные PostgreSQL находятся только в серверной конфигурации и не раскрываются в браузере.
- PostgreSQL хранит идентификатор вещи, утверждённые пользователем название и характеристики, а также относительный идентификатор/ключ фотографии; обработанный файл хранится в выбранной локальной постоянной папке. Полный путь на компьютере не передаётся как публичный идентификатор. Пользовательские правки имеют приоритет перед результатами AI.
- Успешное сохранение показывается только после сохранения фотографии и описания. При ошибке прежние данные не теряются, доступна повторная попытка. Недоступность OpenAI не мешает читать и редактировать сохранённые вещи.
- Фотографии хранятся вне `public`, директорий сборки и временных директорий, не включаются в Git. Сервер проверяет реальное содержимое, формат и размер файла и назначает безопасное имя. При отсутствии сохранённой фотографии интерфейс показывает понятное состояние.
- Локальное хранение относится к данным приложения: для распознавания фотография отправляется в OpenAI. Это должно быть понятно пользователю.
- Восстановление выполняется из согласованной резервной копии PostgreSQL и соответствующего набора фотографий с сохранением связей. Простое копирование файлов работающей БД не считается резервной копией. Отдельный интерфейс экспорта и автоматического резервного копирования в текущую версию не входит.

### 12.6. Требования к AI, бюджету и времени ожидания

**Распознавание и подбор:**

- Из фотографии получается структурированное описание, которое пользователь проверяет и редактирует перед сохранением.
- Для подбора используются погодные данные и проверенные описания гардероба; все фотографии повторно не отправляются. При наличии подходящих сочетаний модель возвращает от одного до трёх образов с идентификаторами выбранных вещей. Сервер проверяет существование вещей и соблюдение погодных правил перед показом результата.
- Предусмотрена предварительная проверка качества примерно на 20 фотографиях и 10 погодных сценариях. Проверяются распознавание, отсутствие выдуманных свойств и подбор из реальных вещей. Комфортный температурный диапазон остаётся приблизительной оценкой, доступной для исправления пользователем.
- Доступность стартовых моделей, качество, скорость и стоимость проверяются при реализации.

**Расходы и повторные операции:**

- Общий бюджет AI приложения — до $10 за календарный месяц UTC допуска операции: распознавание, подбор, чат, разработка и тесты. При расходе $8 показывается предупреждение. Готовый каталог фонов расходов AI не создаёт.
- Перед новой платной операцией сервер проверяет остаток бюджета с учётом резерва для выполняющихся операций и резервирует расход новой операции. Ведётся учёт модели, типа операции и расхода.
- Запросы чата проходят ту же серверную проверку бюджета и резервирование; дубли отправки не создают дополнительных платных операций. Открытие окна и загрузка страницы не запускают AI, запрос выполняется только при отправке сообщения, без автоматических повторов.
- Ограничение бюджета относится только к запросам нашего приложения и не ограничивает стороннее использование аккаунта OpenAI.
- Обновление страницы и дублирующие нажатия не запускают новые генерации. Редактирование карточки не запускает повторное распознавание.
- После таймаута автоматического платного повтора нет; повторная попытка запускается пользователем вручную. При ошибке загрузки изображения каталога показывается default-фон.
- При исчерпании бюджета новые платные операции недоступны, но чтение, редактирование и просмотр готовых результатов продолжают работать.

**Время ожидания:**

| Операция | Целевое время | Предел ожидания |
| --- | --- | --- |
| Распознавание одежды | 15 секунд | 30 секунд |
| Подбор образов | 10 секунд | 30 секунд |

Целевые значения не являются гарантией провайдера и могут корректироваться после измерений. Таймаут ожидания не гарантирует остановку операции у провайдера или отсутствие оплаты.

### 12.7. Требования к погодным сервисам и кешированию

**Сервисы и местоположение:**

- Погодные запросы выполняет сервер Next.js через [Open-Meteo Forecast](https://open-meteo.com/en/docs). Текущие условия рассчитаны погодными моделями, а не являются непосредственным измерением в точке пользователя.
- Ручной поиск использует [Open-Meteo Geocoding](https://open-meteo.com/en/docs/geocoding-api): список результатов позволяет различить город, регион и страну. С выбранным местом сохраняются проверенные координаты и часовой пояс.
- Для некоммерческого локального этапа используется бесплатный API; в интерфейсе размещается атрибуция со ссылкой на Open-Meteo согласно [условиям сервиса](https://open-meteo.com/en/pricing).
- ipapi.co остаётся одобренным кандидатом: один браузерный запрос получает публичный IP и местоположение, без отдельного сервиса определения IP и без секретов в клиенте. При сохранённом городе запрос не повторяется.
- Фактическая доступность [пробного режима ipapi.co](https://ipapi.co/free/) проверяется при реализации. Пробный период ограничен; для доступа может потребоваться обращение к провайдеру. Постоянный бесплатный доступ не обещается, платный тариф сейчас не подключается. При недоступности автоопределения остаётся ручной выбор.

**Кеш и актуальность:**

- Погода кешируется на сервере на 15 минут по координатам и параметрам запроса, а не по названию города. Результаты поиска мест — на 24 часа по поисковому запросу и его параметрам.
- Публичные погодные данные и результаты поиска кешируются отдельно от персональных данных. Гардероб не включается в общий кеш.
- Срок кеша определяет повторное использование ответа и не гарантирует обновление прогноза у провайдера. Время получения данных и период действия погодных значений отображаются отдельно.
- При ошибке старый ответ может показываться только с пометкой «устаревшие данные»; новый подбор на его основе не запускается. Обновление погоды само не вызывает платную операцию AI.

**Период подбора:**

- При запуске фиксируются начало и конец периода «сейчас + 3 часа» в часовом поясе выбранного города. Данные покрывают весь интервал, даже при переходе через полночь.
- Для всего интервала учитываются диапазоны обычной и ощущаемой температуры, ветер и порывы, ожидаемые осадки и их вероятность. Правила обработки погодных значений учитывают период, к которому они относятся, согласно [документации Forecast](https://open-meteo.com/en/docs).
- Период, погодные данные и состояние гардероба сохраняются с результатом подбора. Обновление страницы не сдвигает период; по его окончании или изменении исходных данных результат требует обновления новым явным запуском пользователем.
